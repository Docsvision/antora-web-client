Диагностические журналы параметров производительности сохраняются отдельно в формате `.tsv`. В приведённой ниже конфигурации `NLog` цели и правила для них уже настроены. Чтобы включить диагностическое журналирование, задайте параметр `EnableDiagnosticsLogger` и используйте запросы из раздела "xref:log-config.adoc#advanced-logging[Расширенное журналирование]".

[#config]
== Настройка журналирования

// tag::webconfig[]
.Чтобы изменить настройки:
. Откройте конфигурационный файл `{webconfig-lin}` в Linux и `{webconfig-cp}` в Windows.
. Отредактируйте параметры в секции `NLog`. Чтобы журналирование велось в формате JSON, задайте параметры в секции `variables`.
+
.Фрагмент конфигурационного файла {wc}а:
[source,json]
----
{
  "NLog": {
    "throwConfigExceptions": false, <.>
    "extensions": [ <.>
      { "assembly": "NLog.Extensions.Logging" },
      { "assembly": "NLog.Web.AspNetCore" },
      { "assembly": "DocsVision.WebClient" }
    ],
    "variables": { <.>
      "fileLogLevel": "Error", <.>
      "consoleLogLevel": "Error", <.>
      "enableFileLogging": "true", <.>
      "enableConsoleLogging": "true", <.>
      "jsonLayout": { <.>
        "type": "JsonLayout", <.>
        "includeAllProperties": true, <.>
        "attributes": [ <.>
          {
            "name": "timestamp", <.>
            "layout": "${date:format=yyyy-MM-dd HH\\:mm\\:ss.fff}" <.>
          },
          {
            "name": "level",
            "layout": "${level:upperCase=true}"
          },
          {
            "name": "module",
            "layout": "${logger}"
          },
          {
            "name": "message",
            "layout": "${message:withException=true}" <.>
          },
          {
            "name": "processId",
            "layout": "${processid}"
          }
        ]
      }
    },
    "targets": { <.>
      "async": true, <.>
      "logFile": { <.>
        "type": "File", <.>
        "fileName": "${gdc:docsvisionLogFolder}/${gdc:moduleName}/${gdc:moduleName}.log", <.>
        "layout": "${var:jsonLayout}", <.>
        "archiveEvery": "Day", <.>
        "archiveAboveSize": 314572800, <.>
        "archiveFileName": "${gdc:docsvisionLogFolder}/${gdc:moduleName}/archives/${gdc:moduleName} {#}.log", <.>
        "archiveNumbering": "DateAndSequence", <.>
        "archiveDateFormat": "yyyy-MM-dd", <.>
        "maxArchiveFiles": 30, <.>
        "createDirs": true <.>
      },
      "logConsole": { <.>
        "type": "Console",
        "layout": "${var:jsonLayout}"
      },
      "diagnosticsLogWebClient": { <.>
        "type": "File",
        "fileName": "${gdc:docsvisionLogFolder}/${gdc:moduleName}/DiagnosticsLogWebClient${event-properties:item=Tenant} PID ${processId} ${shortdate}.tsv"
      },
      "diagnosticLogStorageServer": { <.>
        "type": "File",
        "fileName": "${gdc:docsvisionLogFolder}/${gdc:moduleName}/DiagnosticLogStorageServer${event-properties:item=Tenant} PID ${processId} ${shortdate}.tsv"
      }
    },
    "rules": [ <.>
      {
        "logger": "Microsoft.*",
        "maxLevel": "Warn",
        "final": true
      },
      {
        "logger": "DiagnosticsLogWebClient",
        "minLevel": "Trace",
        "writeTo": "diagnosticsLogWebClient",
        "final": true <.>
      },
      {
        "logger": "DiagnosticLogStorageServer",
        "minLevel": "Trace",
        "writeTo": "diagnosticLogStorageServer",
        "final": true
      },
      {
        "logger": "*",
        "minLevel": "${when:when='${var:enableFileLogging:lowercase=true}' == 'true':inner=${var:fileLogLevel}:else=Off}",
        "writeTo": "logFile"
      },
      {
        "logger": "*",
        "minLevel": "${when:when='${var:enableConsoleLogging:lowercase=true}' == 'true':inner=${var:consoleLogLevel}:else=Off}",
        "writeTo": "logConsole"
      }
    ]
  }
}
----
<.> `throwConfigExceptions` -- определяет поведение приложения при обнаружении ошибок в конфигурации NLog.
+
Если параметр установлен в `true`, любая ошибка в конфигурации вызовет исключение.
+
<.> `extensions` -- загружает дополнительные сборки (`.dll`), расширяющие возможности NLog.
<.> `variables` -- раздел определяет параметры, которые используются в других частях конфигурации.
<.> `fileLogLevel` -- задаёт уровень журналирования для файла журнала.
<.> `consoleLogLevel` -- задаёт уровень журналирования для консоли (stdout/stderr).
<.> `enableFileLogging` -- включает или отключает ведение журнала в файл.
<.> `enableConsoleLogging` -- включает или отключает ведение журнала в консоль (stdout/stderr).
<.> `jsonLayout` -- определяет JSON-структуру сообщений журнала.
<.> `type` -- указывает на использование JSON-макета.
<.> `includeAllProperties` -- регулирует, будут ли добавляться в вывод все дополнительные свойства, переданные в контексте журналирования.
<.> `attributes` -- раздел с парными параметрами вида `"name"`/`"layout"`, определяющий поля JSON.
<.> `name` -- значение `timestamp` добавляет отметку времени.
<.> `layout` -- значение `$&#123;date:format=yyyy-MM-dd HH\\:mm\\:ss.fff&#125;` задаёт формат отображения времени.
<.> `layout` -- значение `$&#123;message:withException=true&#125;` добавляет сведения об исключении к тексту сообщения.
<.> `targets` -- настройки режимов журналирования.
<.> `async` -- регулирует асинхронную обработку целей, указанных в этом блоке. Журналирование выполняется в фоновом режиме, не блокируя работу системы, что повышает производительность при высокой нагрузке.
<.> `logFile` -- настройки для режима вывода журнала в файл.
<.> `type` -- указывает на использование файла.
<.> `fileName` -- формирует шаблон имени файла, в параметре можно использовать https://github.com/nlog/NLog/wiki/File-target[допустимые для NLog переменные].
<.> `layout` -- ссылка на общий JSON-формат, определённый в `jsonLayout`.
<.> `archiveEvery` -- создавать новый архивный файл каждый заданный период, по умолчанию -- каждый день.
<.> `archiveAboveSize` -- если текущий файл превышает `300` Мб (значение по умолчанию), он будет немедленно архивирован, даже если заданный в `archiveEvery` период не завершился.
<.> `archiveFileName` -- шаблон имени для архивов, `&#123;#&#125;` заменяется на номер архива.
<.> `archiveNumbering` -- значение `DateAndSequence` задаёт нумерацию архивов по дате и порядковому номеру (например, `MyLog 2026-09-09 1.log`).
<.> `archiveDateFormat` -- задаёт формат даты, которая подставляется в имя архивного файла при архивации журнала.
<.> `maxArchiveFiles` -- максимальное количество архивных файлов, после которого старые файлы будут удаляться. По умолчанию -- `30`.
<.> `createDirs` -- флаг регулирует автоматическое создание каталогов журналов. Каталоги будут создаваться автоматически, когда флаг в значении `true`.
<.> `logConsole` -- настройки для режима вывода журнала в stdout/stderr процесса, например _journald_ в терминале Linux. Формат -- тот же JSON, что и для файла.
<.> `diagnosticsLogWebClient` -- настройки файла диагностического журнала запросов {wc}а. Журнал сохраняется в формате TSV.
<.> `diagnosticLogStorageServer` -- настройки файла диагностического журнала запросов к службе Сервера {dv}. Журнал сохраняется в формате TSV.
<.> `rules` -- правила журналирования. Определяют, какой логгер (`logger`), с каким уровнем (`minLevel`, `maxLevel`) и в каком режиме (`writeTo`) будет писать сообщения.
+
Допустимые уровни протоколирования приведены https://github.com/nlog/NLog/wiki/Configuration-file#log-levels[на странице NLog в GitHub]. +
Дополнительная информация о прочих настройках NLog приводится в документации по данной платформе.
<.> `final` -- значение `true` в правилах `DiagnosticsLogWebClient` и `DiagnosticLogStorageServer` прекращает обработку диагностических сообщений последующими правилами. Эти сообщения не попадают в основной JSON-журнал и консоль.
+
. Сохраните изменения конфигурационного файла.
// end::webconfig[]

NOTE: Для приведённой конфигурации уровень журналирования изменяется параметрами `fileLogLevel` и `consoleLogLevel` в секции `NLog.variables`. Метод `/Log/SetLogLevel` рассчитан на прежнюю конфигурацию с целью `DefaultLogFileAsync` и не изменяет уровни `logFile` и `logConsole`.

[#advanced-logging]
== Расширенное журналирование

{wc} поддерживает расширенное журналирование параметров производительности. Сюда входит точное логирование времени выполнения запросов {wc}а, время выполнения запросов к службе Сервера {dv} с привязкой к запросу {wc}а.

Для настройки доступно три фильтра журнала: По пользователю, По конкретному адресу, По времени запроса.

После включения диагностического логирования можно делать запросы. Если в параметре будет слеш (`\` или `/`), его необходимо переводить в URL код. Иными словами, заменять `example\usr01` на `example%5Cusr01`.

.Для отдельного запроса {wc}а можно посмотреть:
* Какие запросы к службе Сервера {dv} выполнялись.
* Время, потраченное на выполнение каждого из них.
* Время, проведённое запросами на стороне службы Сервера {dv} и на стороне {wc}а.
* Параметры запросов.

.Эта информация позволяет:
* Устанавливать причины аномально быстрого или медленного выполнения запроса {wc}а.
* Выявлять ошибки и неоптимальные места в работе {wc}а и Object Manager.
* Обнаруживать блокировки {wc}а и Object Manager.
* Выявлять проблемные запросы на сервере.

Чтобы включить диагностическое логирование, нужно в конфигурационном файле {wc}а для параметра `EnableDiagnosticsLogger` в разделе {cnf-sgrps} > "System"] указать значение `1`:

[source,json]
----
{
  "Docsvision": {
    "WebClient": {
      "SettingGroups": {
        "System": {
          "EnableDiagnosticsLogger": "1" <.>
        }
      }
    }
  }
}
----
<.> Включить расширенное журналирование.

Настроить параметры журналирования можно в конфигурационном файле следующим образом:

[source,json]
----
{
  "targets": {
    "async": true,
    "logFile": {
        "type": "File",
        "fileName": "${gdc:baseLogFolder}/docsvision/webclient/webclient.log",
        "layout": "[${longdate}][${level}][${callsite}] ${message} ${onexception:${newline}${exception:maxInnerExceptionLevel=10:format=shortType,message,stacktrace:separator=*:innerExceptionSeparator=&#xD;&#xA;&#x9;}}"
    },
    "logConsole": {
        "type": "Console"
    },
    "diagnosticsLogWebClient": {
        "type": "File",
        "fileName": "${gdc:baseLogFolder}/docsvision/webclient/DiagnosticsLogWebClient${event-properties:item=Tenant} PID ${processId} ${shortdate}.tsv" <.>
    },
    "diagnosticLogStorageServer": {
        "type": "File",
        "fileName": "${gdc:baseLogFolder}/docsvision/webclient/DiagnosticLogStorageServer${event-properties:item=Tenant} PID ${processId} ${shortdate}.tsv" <.>
    }
  },
  "rules": [ <.>
    {
      "logger": "DiagnosticsLogWebClient",
      "minLevel": "Trace",
      "writeTo": "diagnosticsLogWebClient"
    },
    {
      "logger": "DiagnosticLogStorageServer",
      "minLevel": "Trace",
      "writeTo": "diagnosticLogStorageServer"
    },
  ]
}
----
<.> Адрес хранения журнала {wc}а. В параметре важно добавить в имя файла `$\{processId}`, например, `WebCDiagnostics PID$\{processId}.log`, а также указать `layout="$\{message}"`.
<.> Адрес хранения журнала службы Сервера {dv}. В параметре важно добавить в имя файла `$\{processId}`, например, `WebCDiagnostics PID$\{processId}.log`, а также указать `layout="$\{message}"`.
<.> Обязательные разделы для работы расширенного журналирования.

Журнал ведётся в формате `.tsv` и в дальнейшем может быть проанализирован через приложение для работы с журналами, например Log Parser Studio. Расширенный журнал по умолчанию сохраняется в стандартный каталог журналов {wc}а, но при помощи параметров конфигурации NLog можно записать в иной каталог.

Чтобы включить ведение расширенного журнала с требуемым фильтром, нужно выполнить в браузере запрос. Примеры запросов приведены далее.

[#query-sample]
=== Примеры запросов

. Запрос включения журнала для всех пользователей:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogUser?user=*
+
Журналируются все запросы `example\usr01`:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogUser?user=example%5Cusr01
+
. Запрос включения журнала по адресу:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogAddress?address=Grid%2FGetGridDataEx
+
Журналируются все запросы, в имени которых содержится подстрока `Grid/GetGridDataEx`. При необходимости можно журналировать все запросы конкретного контроллера:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogAddress?address=Grid
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogAddress?address=*
+
. Запрос включения журнала по времени выполнения запросов:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogRequestTime?milliseconds=500
+
. Запрос установки таймера журналирования с указанием времени работы 10 минут:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/SetIntervalTimer?minutes=10
+
.Принцип работы запроса :
[%collapsible%open]
====
Вызов запроса `SetIntervalTimer` не включает журналирование. Для журналирования должен быть указан конкретный фильтр (`AddLogUser`, `AddLogAddress` или `AddLogRequestTime`), который будет вызван до или после запроса `SetIntervalTimer`. Запрос `SetIntervalTimer` может быть выполнен в любой момент до или после установки фильтров. При его выполнении таймер перезапускается. Т.е. если нужно продлить время журналирования, достаточно выполнить этот запрос ещё раз.

Указание таймера в параметре `SetIntervalTimer` не является обязательным, в таком случае журналирование всех запросов по умолчанию будет длиться 1 час. Даже после сброса с помощью `Reset` запроса. Пользовательское значение таймера сбрасывается на значение по умолчанию после перезапуска службы Сервера {wc}а (т.е. значение времени таймера хранится в кэше {wc}а).

Время работы таймера отсчитывается с момента последнего запроса к API журналирования.
====
+
. Фильтры можно комбинировать. Ниже приведён пример включения фильтра для пользователя `example\usr01`, адреса `Grid/GetGridDataEx`, времени выполнения запросов `50` мс:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogUser?user=example%5Cusr01
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogAddress?address=Grid%2FGetGridDataEx
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/AddLogRequestTime?milliseconds=50
+
. Чтобы отключить ведение расширенного журнала, нужно выполнить запрос в браузере:
+
[subs=attributes]
 http://адрес-сервера-{wc}а:ПОРТ/DiagnosticsLog/Reset
